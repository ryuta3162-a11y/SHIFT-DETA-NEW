# Webアプリ骨格 — 貼り付け・デプロイ

対象スプシ: [新 シフト『キンタイ・カレンダー』管理](https://docs.google.com/spreadsheets/d/1mPb5xUeoDoT5--yEXqUw5bY0PBpQ2AWSo17zkWML4ww/edit)

## Apps Script に入れるファイル

同じプロジェクトに **3つ**（セットアップ済みなら Setup は既存のまま）:

| GAS上の名前 | リポジトリのファイル |
|-------------|----------------------|
| `SetupSheets`（既存） | `docs/gas/SetupSheets.gs` |
| `コード` または `Code` | [`Code.gs`](./Code.gs) |
| `index`（HTML） | [`index.html`](./index.html) |

### 手順

1. スプシ → **拡張機能 → Apps Script**
2. 既存の `SetupSheets` はそのまま
3. **ファイルを追加**（`+`）→ スクリプト → 名前を `Code`（または既存のコード.gsを置き換え）→ [`Code.gs`](./Code.gs) を全部貼る
4. **ファイルを追加** → HTML → 名前を必ず `index` → [`index.html`](./index.html) を全部貼る
5. 保存

### ウェブアプリとしてデプロイ

1. **デプロイ → 新しいデプロイ**（または **デプロイを管理 → 編集**）
2. 種類: **ウェブアプリ**
3. 設定（重要）:
   - **実行ユーザー: ウェブアプリにアクセスしているユーザー**
   - **アクセスできるユーザー: ○○内の全員**（会社ドメイン）
4. **新しいバージョン** を選んでデプロイ → URL を控える

#### 「ログインメールを取得できません」と出るとき

ほとんどがデプロイ設定です。

1. Apps Script → **デプロイ → デプロイを管理 → ✎編集**
2. 「実行ユーザー」を **アクセスしているユーザー** に変更
3. 「バージョン」を **新しいバージョン** にする
4. デプロイ → 表示された **/exec** URL を開き直す（古いURLのままだと古い設定のまま）
5. 会社アカウント（例: `@okamoto-group.co.jp`）でログインしているか確認
6. 初回は承認画面が出るので許可

**注意（実行ユーザーを「アクセスしているユーザー」にした場合）**  
スクリプトはその人の権限でスプシを読むため、**組織内のメンバーがスプシを読める共有**が必要になることがあります（閲覧のみで可）。  
スプシのURLは配らず、WebのURLだけ渡す運用にしてください。

試験だけ先に進めたい場合は、設定シートに次を追加してもよいです（本番前に外す）:

| key | value |
|-----|--------|
| allow_effective_user_fallback | TRUE |

→ 実行ユーザーが「自分」でも、デプロイ者のメールとして動きます（権限チェックもデプロイ者扱い）。

## 今できること

- Googleログイン後、**権限シートに載った店舗だけ**表示
- 年月を選んでシフト一覧
- editor / admin は追加・編集・削除（スプシの「シフト」シートに保存）

## まだないこと（次の段）

- カレンダー風の月間グリッドUI
- シフトメモ
- Googleカレンダー同期／バイバイ貼り付け（`gas-kyodo` 移植）

## 動作確認の前に

1. **権限**シートに自分のメールがあること（セットアップサンプルの admin 行）
2. **従業員マスタ**に少なくとも1名いること（シフト追加用）
3. スプシ共有は DXのみのまま（現場には Web URL だけ渡す）
